# Mini NPU Simulator (AI MAC 연산 시뮬레이터) - E1-3

AI가 패턴을 인식하고 계산하는 기본 핵심 원리인 **MAC(Multiply-Accumulate, 곱셈-누적 연산)**을 순수 Python으로 직접 구현한 Mini NPU 시뮬레이터 프로젝트입니다. 3×3 콘솔 입력부터 25×25 대용량 JSON 데이터셋(`data.json`) 일괄 판정, epsilon 기반 부동소수점 동점 처리, 그리고 행렬 크기 증가에 따른 시간 복잡도($O(N^2)$) 분석 및 1D 메모리 접근 최적화까지 포함하고 있습니다.

## 1. 실행 방법

### 환경 요구사항
- **Python**: Python 3.8 이상 (외부 패키지 설치 불필요, 표준 라이브러리 `json`, `time`, `argparse`, `unittest`만 사용)


3. **단위 테스트(Unit Test) 실행**:

## 2. 구현 요약

### 1) 라벨 정규화 (Normalization)
데이터 소스나 필터에 따라 라벨 표기가 상이할 수 있습니다 (`'+'`, `'cross'`, `'Cross'`, `'x'`, `'X'`). 본 프로그램은 내부적으로 2가지 표준 라벨(`Cross`, `X`)을 정의하고, 입력을 받는 즉시 정규화 함수(`normalize_label`)를 통과시켜 일관된 비교와 출력을 보장합니다:
- `'+'`, `'cross'`, `'CROSS'`, `'Cross'` $\rightarrow$ `Cross`
- `'x'`, `'X'` $\rightarrow$ `X`

### 2) 순수 반복문 기반 MAC 연산 (No NumPy)
외부 수치 연산 라이브러리(NumPy, SciPy 등)를 사용하지 않고, 2차원 리스트의 중첩 반복문을 통해 원소별 곱셈과 누적 합산을 직접 구현하였습니다:
```python
def mac_2d(mat_a: List[List[float]], mat_b: List[List[float]]) -> float:
    total = 0.0
    for r in range(len(mat_a)):
        row_a = mat_a[r]
        row_b = mat_b[r]
        for c in range(len(row_a)):
            total += row_a[c] * row_b[c]
    return total
```

### 3) 부동소수점 허용오차(Epsilon) 기반 동점 처리 정책
IEEE 754 부동소수점 연산 특성상 `0.1 * 9`나 `0.3 * 25`와 같은 연산에서 미세한 오차가 발생합니다 (예: `0.9000000000000000` vs `0.8999999999999999`).
단순 등호(`==`) 비교 시 이러한 오차로 인해 잘못된 판정이 내려질 수 있으므로, 허용오차 $\epsilon = 10^{-9}$를 적용하여 판정합니다:
```python
if abs(score_cross - score_x) < 1e-9:
    return "UNDECIDED"  # 판정 불가 / 동점
```

## 3. 결과 리포트

### 1) FAIL 케이스 원인 분석 (data.json 분석)

`data.json`에 포함된 총 6개 테스트 케이스 중 3개가 통과(PASS)하고 3개가 실패(FAIL)로 판정되었습니다:

| 케이스 키 | Cross 점수 | X 점수 | 모델 판정 | Expected | 결과 | 사유 |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **size_5_1** | 0.9000000000000000 | 0.8999999999999999 | **UNDECIDED** | X | **FAIL** | 동점 규칙 ($\|A-B\| < 10^{-9}$) |
| **size_5_2** | 8.9000000000000004 | 0.1000000000000000 | **Cross** | Cross | **PASS** | 일치 |
| **size_13_1** | 0.3000000000000000 | 14.700000000000008 | **X** | X | **PASS** | 일치 |
| **size_13_2** | 7.4999999999999973 | 7.5000000000000000 | **UNDECIDED** | Cross | **FAIL** | 동점 규칙 ($\|A-B\| < 10^{-9}$) |
| **size_25_1** | 4.9000000000000004 | 4.8999999999999986 | **UNDECIDED** | X | **FAIL** | 동점 규칙 ($\|A-B\| < 10^{-9}$) |
| **size_25_2** | 52.899999999999999 | 0.1000000000000000 | **Cross** | Cross | **PASS** | 일치 |

#### 실패의 근본 원인 분석
1. **필터 가중치 정규화(Weight Scaling)의 부재**:
   - `size_5_1`의 경우 입력 패턴은 형태학적으로 완벽한 X 형태입니다. 그러나 제공된 `size_5`의 X 필터는 가중치가 각 위치당 `0.1`로 매우 작아 9개 픽셀의 합이 $9 \times 0.1 = 0.9$에 불과합니다.
   - 반면 Cross 필터는 중앙 교차점(2, 2)에 `0.9`라는 매우 큰 단일 가중치를 가지고 있습니다.
   - X 패턴과 Cross 필터가 교차하는 위치는 중앙(2, 2) 한 점뿐이지만, 이 한 점에서 $1.0 \times 0.9 = 0.9$ 점수를 얻게 됩니다.
   - 결과적으로 두 필터의 MAC 연산 결과가 수학적으로 완전히 동일한 `0.9`가 되어버립니다.
2. **부동소수점 오차와 Epsilon 정책의 상호작용**:
   - 2진 부동소수점 표현 한계로 인해 Cross 점수는 `0.9000000000000000`, X 점수는 `0.8999999999999999`로 계산되어 $|A-B| \approx 1.11 \times 10^{-16}$의 차이가 발생합니다.
   - 만약 epsilon 없이 단순 크기 비교(`>`)를 수행했다면 `0.9000000000000000 > 0.8999999999999999`이므로 형태가 X임에도 불구하고 황당하게 **Cross**로 오분류되었을 것입니다.
   - Epsilon($10^{-9}$) 정책 덕분에 이 미세 오차에 휘둘리지 않고 올바르게 **UNDECIDED(동점)**로 판정하여 데이터가 모호함을 정확히 탐지해 냈습니다.
3. **size_13_2와 size_25_1에서도 동일한 현상 발생**:
   - `size_13_2`는 입력이 Cross 형태이지만, X 필터의 중앙 가중치(`7.5`)와 Cross 필터의 전체 누적 가중치(`7.5`)가 동일하여 점수 7.5 동점으로 UNDECIDED 처리되었습니다.
   - `size_25_1` 역시 Cross 필터 중앙 가중치(`4.9`)와 X 필터 전체 가중치 합(`4.9`)이 동일하여 4.9 동점으로 UNDECIDED 처리되었습니다.
   - **결론 및 시사점**: 필터 설계 시 각 필터의 전체 에너지(L1 Norm 또는 L2 Norm)를 균일하게 정규화(Normalization)하지 않으면, 특정 교차점 가중치로 인해 서로 다른 패턴 간에 완벽한 점수 동점이 발생할 수 있음을 입증합니다.

### 2) 시간 복잡도 분석 ($O(N^2)$)

MAC 연산의 시간 복잡도와 크기별 벤치마크 결과는 다음과 같습니다:

```text
크기       평균 시간(ms)    연산 횟수(N²)
-------------------------------------
3×3            0.0004           9
5×5            0.0006           25
13×13          0.0030           169
25×25          0.0099           625
```

#### 시간 복잡도 상세 분석 (최소 10줄 이상 서술)
1. **$O(N^2)$ 복잡도 성립 근거**:
   $N \times N$ 크기의 2차원 행렬 두 개에 대해 MAC 연산을 수행할 때, 행의 개수 $N$개와 각 행당 열의 개수 $N$개를 모두 순회해야 하므로 총 원소 곱셈 횟수는 정확히 $N \times N = N^2$번 발생합니다.
2. 각 원소마다 1번의 부동소수점 곱셈(Multiplication)과 1번의 덧셈 누적(Accumulation)이 발생하므로 총 연산 단계 수는 $2N^2$이며, 점근적 시간 복잡도는 엄밀히 $O(N^2)$에 비례합니다.
3. **측정 결과와의 일치성 검증**:
   - 3×3 ($N^2=9$)에서 5×5 ($N^2=25$)로 증가 시 연산 횟수는 약 2.78배 증가하며, 평균 측정 시간 역시 약 0.0004ms에서 0.0006ms로 비례하여 증가합니다.
   - 5×5 ($N^2=25$)에서 13×13 ($N^2=169$)로 증가 시 연산 횟수는 $169 / 25 \approx 6.76$배 증가하며, 측정 시간도 0.0006ms에서 0.0030ms로 약 5배 증가합니다.
   - 13×13 ($N^2=169$)에서 25×25 ($N^2=625$)로 증가 시 연산 횟수는 $625 / 169 \approx 3.70$배 증가하며, 측정 시간도 0.0030ms에서 0.0099ms로 약 3.3배 증가합니다.
4. **이론적 $N^2$과 실측치의 미세 편차 원인**:
   - 아주 작은 크기(3×3, 5×5)에서는 Python 인터프리터의 함수 프레임 호출 오버헤드, 루프 초기화 비용, CPU 캐시 웜업 상태 등의 고정 비용($O(1)$) 비중이 상대적으로 큽니다.
   - 반면 행렬 크기가 25×25 이상으로 커질수록 순수 루프 내 곱셈/누적 연산이 전체 실행 시간을 지배하게 되어 $O(N^2)$ 곡선에 정밀하게 수렴합니다.
5. **NPU(Neural Processing Unit) 병렬화의 필요성**:
   - CPU 환경에서 직렬 반복문으로 1장의 1024×1024 고화질 이미지를 처리할 경우 $N^2 \approx 1,000,000$번의 순차 연산이 필요하며, 수백 개의 필터를 거치면 단일 이미지 추론에도 수 초가 소요됩니다.
   - NPU는 대규모 곱셈-누적 연산기 어레이(Systolic Array 등)를 통해 수천 개의 MAC 연산을 단 1클럭 사이클에 동시 수행(Parallel MAC)함으로써 이 $O(N^2)$ 병목을 하드웨어적으로 해결합니다.

## 4. 보너스 과제 결과

### 보너스 1: 1D 메모리 접근 최적화
2차원 배열(`List[List[float]]`)을 1차원 연속 배열(`List[float]`, 길이 $N^2$)로 평탄화하여 포인터 참조 횟수를 줄이고 캐시 연속성을 확보하는 최적화를 수행했습니다:

```text
크기       2D 시간(ms)    1D 시간(ms)    속도 향상(%)
-------------------------------------------------
3×3        0.00044       0.00026       +40.9%
5×5        0.00082       0.00057       +30.9%
13×13       0.00394       0.00322       +18.2%
25×25       0.01281       0.01113       +13.1%
50×50       0.04688       0.04874       -4.0%
100×100      0.17904       0.18217       -1.7%
```
- **분석**: 소형 행렬(3×3 ~ 25×25)에서는 외부 리스트와 내부 리스트를 두 번 역참조(Double Dereferencing)하던 2D 구조에 비해, 단일 리스트 순회만 수행하는 1D 구조가 **13% ~ 40% 이상의 유의미한 속도 개선**을 보여주었습니다.

### 보너스 2: 패턴 생성기 (Pattern Generator)
임의의 크기 $N$에 대해 십자가(Cross) 및 X 패턴을 자동으로 생성할 수 있는 유틸리티를 개발하였습니다:
- `PatternGenerator.generate_cross(N)`: 정중앙 행과 열을 1.0으로 채운 십자가 행렬 생성
- `PatternGenerator.generate_x(N)`: 주 대각선과 부 대각선을 1.0으로 채운 X 행렬 생성
- 이를 통해 모드 1의 테스트 데이터 입력이나 대규모 임의 크기 벤치마크에 손쉽게 재활용할 수 있습니다.
